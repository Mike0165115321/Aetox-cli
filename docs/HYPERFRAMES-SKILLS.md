> ซึ่งเป็นคนละเรื่องกัน ฟอร์กคือโค้ดที่เรนเดอร์ นี่คือความรู้ที่มากับมัน
>
> **ทุกอย่างในไฟล์นี้จริง ณ 8 ก.ย. 2569**

> **ยังไม่มีใครได้ก้อนนี้** job `hyperframes-skills` **ยังไม่เคยรัน** ยังไม่มีแถวใน
> `Manifest()` และไม่มีปุ่มไหนในแอปที่ติดตั้งมันได้ ตอนนี้ `AgentInstalledSkillsPath`

>
> ตราบใดที่ยังเป็นแบบนี้ **`skills_list` ของเอเจนวิดีโอจะขึ้นรายการเดียว** และ
> AGENT.md เขียนไว้ให้รับสภาพนั้นได้ — มันบอกให้ดูที่ `skills_list` ก่อน แล้วถ้าไม่มี
> ก็บอกไปตรง ๆ ว่าไม่มี ไม่ใช่ประกาศว่ามียี่สิบอันแล้วให้เอเจนไปหาของที่ไม่มีอยู่
> (เคยประกาศแบบนั้นจนถึง 8 ก.ย. 2569)

## เรื่องมันสั้น ๆ

hyperframes เขียนคู่มือของตัวเองเป็น Agent Skills **20 โฟลเดอร์ 904 ไฟล์** และ
แพ็กเกจ npm ที่เราโหลดมาแบกมาแค่ **2 อัน** — `hyperframes` (ตัวจัดเส้นทาง) กับ
`hyperframes-cli` (สัญญาการใช้คำสั่ง) อีก 18 อันเขาให้ดึงตอนใช้งานด้วย

```
hyperframes skills update <ชื่อ>
```

ซึ่งยิงไป GitHub — และเราพิน `HYPERFRAMES_NO_AUTO_INSTALL=1` ไว้ ประตูนั้นปิดอยู่
**18 อันจึงไม่เคยมาถึงเครื่องใคร** เอเจนวิดีโอเดินด้วย AGENT.md ของตัวเองอย่างเดียว
มาตั้งแต่ 30 ส.ค. ส่วนคำอธิบายของเจ้าของเอนจินว่าคอมโพสิชันคืออะไร `data-*` ตัวไหน
ถือเวลา อะไรทำให้แอนิเมชัน seek ได้ — นอนอยู่บนดิสก์โดยไม่มีใครถืออยู่

รอบนี้เอามาทั้ง 20

## กฎข้อเดียวที่ต้องจำ: เวอร์ชันต้องเดินคู่กัน

เขียนนี่ ถ้าเราเอาสกิลของ v0.8.30 มาวางคู่เอนจิน 0.8.20 เอเจนจะอ่านคู่มือที่พูดถึง
แฟล็กที่เครื่องนี้ไม่มี แล้ว**ไม่มีทางรู้ตัวว่ากำลังอ่านหนังสือผิดเล่ม**

เวลาจะขยับ ขยับทั้งคู่ในคอมมิตเดียว: ดิสแพตช์ `hyperframes` แล้วดิสแพตช์

## ทำไมมันไม่ได้ลงในบ้านของเอเจน

`internal/capability` `os.RemoveAll` ตัว `Dest` ทุกครั้งก่อนแตกไฟล์ ถ้าชี้ไปที่
`<DataRoot>/agents/video/skills/` ซึ่งเป็นที่ที่**ผู้ใช้**เก็บสกิลที่เขาเขียนเอง
สกิลของเขาจะหายเกลี้ยงทุกครั้งที่พินขยับ ของที่โหลดมาต้องมีโฟลเดอร์ของตัวเอง

ชั้นวางของเอเจนหนึ่งตัวจึงมีสามที่ เรียงตามลำดับที่ชนะกัน

1. `<DataRoot>/agents/<ชื่อ>/skills/` — สิ่งที่ผู้ใช้เขียนเอง ชนะเสมอ
2. ในไบนารี (`internal/subagent/profiles/agents/<ชื่อ>/skills/`) — ของที่ Aetox ส่งมา
3. `<DataRoot>/tools/agent-skills/<ชื่อ>/` — ของที่โหลดมา แพ้ทั้งสองอันบน

ข้อ 3 เป็นของใหม่ และมันเป็นกลไกทั่วไป ไม่ได้ผูกกับ hyperframes เอเจนตัวอื่นในวันหน้า
ใช้ทางเดียวกันได้ เทสต์อยู่ที่ `internal/subagent/installed_skills_test.go`

## job มันเช็กอะไรให้บ้าง

สามอย่าง และทั้งสามมีเพราะความผิดพลาดจริงที่เคยเกิด

1. **โฟลเดอร์ไหนไม่มี `SKILL.md` job พังทันที** ไม่ใช่ข้ามเงียบ ๆ ถ้าต้นทางเพิ่ม
   สกิลใหม่มันจะติดมาเองโดยไม่ต้องแก้ไฟล์นี้ ถ้าต้นทางทำ `SKILL.md` หาย เราจะรู้
   ตอนบิ้ว ไม่ใช่ตอนเอเจนเปิดไม่เจอ
2. **`hyperframes` กับ `hyperframes-cli` ต้องมี** ขาดอันใดอันหนึ่งก้อนนี้เป็นของ
   ประดับ อันแรกคือประตูที่ทุกคำขอเดินเข้า อันที่สองคือสัญญาของคำสั่ง
3. **นับไฟล์สองรอบ** บนดิสก์รอบหนึ่ง ในซิปที่บีบเสร็จแล้วอีกรอบ ไม่เท่ากันคือพัง
   ข้อนี้มีเพราะ**ความพลาดรอบที่แล้ว**: การเอาเทมเพลตของต้นทางมาครั้งแรกหยิบแค่
   `index.html` ของแต่ละโฟลเดอร์แล้วทิ้งคอมโพสิชันไว้ ฉากแบบนั้นไม่พังเสียงดัง —
   มันเรนเดอร์ออกมาเป็นเฟรมที่ข้างในว่างเปล่า ก้อนที่ไม่ครบต้องปล่อยไม่ได้

## วิธีบิ้วและพิน

```bash
gh workflow run tools.yml -f only=hyperframes-skills -f hyperframes_version=0.8.20
```

job พิมพ์ URL, SHA256, Marker, ApproxBytes ออกมา เอาไปวางใน `Manifest()` เหมือน
ทุกก้อน ไม่ต้องใส่ `node_version` — job นี้ไม่ได้บิ้วอะไร มันแค่หยิบกับบีบ
